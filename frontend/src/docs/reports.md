Once a scan completes, BPS materialises the findings into three downloadable artefacts. Each format targets a different reader: the PDF tells the story, the Excel workbook supports drill-down, and the zip bundle hands you the same content as plain Markdown so you can commit it alongside your code.

> Note: Report generation runs automatically at the end of every successful scan. You do not need to trigger it separately — the "View report" buttons appear on the scan detail page as soon as the files are written.

## Report formats

BPS produces all three formats from a single render pipeline so they are guaranteed to contain the same numbers, the same AI-generated summaries, and the same recommendation list.

### PDF

The PDF is rendered by WeasyPrint from Jinja2 templates in `backend/reports/templates/`. It is the canonical deliverable for executives, customer success teams, and board-level review packs. It contains:

- A branded cover page with overall score, DORA level, customer name, organisation name and the scan timestamp.
- An executive summary written by the customer's default LLM connection.
- A per-category breakdown for all enabled categories, with strengths, weaknesses and the key findings table.
- The prioritised list of recommendations with effort and impact estimates.
- Benchmark comparisons against OpenSSF, DORA, SLSA and CIS.
- An appendix listing every finding with check ID, severity, status and evidence detail.

The PDF respects the report template configured for the customer, including custom accent colour and logo if supplied.

### Excel

The Excel workbook is rendered by openpyxl into six sheets. It is the format security analysts and engineering leads will reach for when they need to pivot, filter or chart the data:

- **Cover** — metadata, overall score, DORA level and platform.
- **Executive Summary** — narrative paragraphs plus risk highlights.
- **Category Scores** — one row per category with score, weight and contribution.
- **Recommendations** — sortable list with priority, effort, impact and the related check IDs.
- **Benchmarks** — framework-by-framework comparison rows.
- **All Findings** — the full unfiltered finding set with check IDs, severities, statuses and the first 100 characters of every evidence detail string.

Column widths auto-fit content (capped at 60 characters) and the header row uses BPS brand blue.

### Zip bundle

The zip bundle pairs the Excel workbook with a `markdown/` folder containing six structured `.md` files generated by `MarkdownRenderer`:

- `00-cover.md`
- `01-executive-summary.md`
- `02-category-detail.md`
- `03-recommendations.md`
- `04-benchmarks.md`
- `05-appendix-findings.md`

This format is designed for teams that want to commit the assessment to a documentation repository, diff it against the previous quarter's output, or render it inside a static site generator. Every table uses GitHub-flavoured Markdown so it renders correctly on GitHub, GitLab and Azure DevOps wikis.

## Generating a report

1. Open the customer detail page and pick a completed scan.
2. Click **Generate report**. The new row appears with status `pending`.
3. The background worker promotes the row to `generating` while WeasyPrint, openpyxl and the Markdown renderer all run in sequence.
4. When the status flips to `completed`, three buttons appear: **Download PDF**, **Download Excel** and **Download Zip**.

If the status stays in `generating` for more than a couple of minutes, see [Troubleshooting](/help/troubleshooting).

## When to use each format

| Audience | Recommended format | Why |
| :--- | :--- | :--- |
| Executives, board members, customer success | PDF | Polished, branded, prints well, contains the AI narrative |
| Security analysts, engineering leads | Excel | Sortable, filterable, pivot-friendly, shows the unfiltered finding set |
| Documentation repositories, git-tracked records, wikis | Zip bundle | Plain Markdown, diffable, renders in any code forge |

A common workflow is to circulate the PDF to leadership, hand the Excel to the engineering team for triage, and commit the unzipped Markdown to the customer's internal documentation repository as the canonical record.

## What's in each

All three formats share the same upstream data structure. The differences are layout and the medium-specific affordances: a clickable table of contents in the PDF, conditional formatting in Excel, GitHub-flavoured tables in Markdown. The AI-written executive summary, category narratives and recommendations are produced by the customer's default LLM connection — see [Configuring LLM providers](/help/llm-providers) for how that is selected. If a customer has no LLM connection configured, BPS falls back to the global default set in Global Settings.

## Storage and retention

Generated files live on the backend disk under `REPORTS_DIR` (defaults to `./reports/`). The `Report` model stores three columns — `pdf_path`, `excel_path` and `zip_path` — as relative paths under `REPORTS_DIR`. The download endpoints resolve those paths through a boundary check that rejects any attempt to escape `REPORTS_DIR` (OWASP A01 path-traversal mitigation).

Retention defaults to 90 days from `Report.created_at`. The window is configurable in Global Settings → Retention if your compliance team requires a different value. Once a file is pruned from disk the row remains in the database for audit purposes but the download endpoints return HTTP 404.

> Tip: If you need to keep an assessment indefinitely, download the zip bundle and commit it to a long-lived documentation repository. The bundle is self-contained and reproducible.

## Downloading via the API

All three download endpoints take a report UUID and stream the file with the correct `Content-Type` header. Useful for CI pipelines that want to attach the latest assessment to a release artefact.

```bash
REPORT_ID="3f8b9c44-2c17-44dc-86e8-7a3b9e1d4f10"
BASE="http://bps.internal.example.com/api"

# Board-ready PDF
curl -fSL -o assessment.pdf \
  "$BASE/reports/$REPORT_ID/download"

# Analyst Excel workbook
curl -fSL -o assessment.xlsx \
  "$BASE/reports/$REPORT_ID/download/excel"

# Markdown + Excel zip bundle (suitable for git)
curl -fSL -o assessment.zip \
  "$BASE/reports/$REPORT_ID/download/zip"
```

The PDF endpoint is the legacy one, hence the unqualified path. The Excel and zip endpoints follow the `/download/{format}` convention.
